Présentation du codage par substitution (extrait du TP d’Informatique de base - groupe avancé) (5mn)

Le chiffrement par substitution consiste à remplacer, dans un message, chaque lettre par une autre
lettre. Deux lettres égales dans le texte original doivent être chiffrées de la même manière, et deux lettres
différentes doivent être chiffrées différemment. C’est comme si on prenait les lettres de l’alphabet, rangées
par ordre croissant, qu’on les mélangeait (obtenant alors un nouvel alphabet) et qu’on utilisait le nouvel
alphabet pour chiffrer notre message : les "a" de notre message deviendraient alors la première lettre de
notre nouvel alphabet, etc...
Par exemple, considérons cette substitution :

Remarquez que le chiffrement de César (où chaque lettre est décalée d’un même nombre de cran

ne prendrons pas en compte les lettres accentuées ni les signes de ponctuation dans notre système de
cryptage.

Notre constructeur prendra comme paramètre une chaîne de caractères pwd, représentant

Création d’une classe de décodage permettant de réaliser le
déchiffrement d’un texte (30mn)

Dans la suite, vous créerez une classe de décodage permettant de décoder un texte à partir du mot
de passe ayant permis le chiffrement de ce dernier.
L’idée centrale ici est, que pour réaliser le décodage d’un texte, il suffit de recoder le texte chiffré avec
le mot de passe "inverse" de celui utilise pour le codage. Si toutes les lettres ’a’ avaient été transformées
en ’u’, il faudra, dans le décodage, que toutes les lettres ’u’ soient transformées en ’a’.
Pour construire le mot de passe "inverse", il faudra donc que, si la première lettre du mot de passe de
cryptage était ’u’ (21ème lettre de l’alphabet), la 21ème lettre du mot de passe inverse soit ’a’. Essayez,
sur papier, d’écrire un mot de passe au hasard, puis de construire le mot de passe inverse.
Questions
1. Construisez une classe Decodeur avec un constructeur prenant en paramètre le mot de
passe de codage que l’on souhaite inverser. Votre constructeur inversera le mot de passe, et
initialisera un objet Encodeur avec ce mot de passe inverse.
Pour ce faire, commencez par construire des paires d’éléments à l’aide de zip : chaque
lettre du mot de passe de cryptage doit être associée avec la lettre, dans l’alphabet, qui
correspond à sa position dans le mot de passe. Par exemple, si le mot de passe de cryptage
commence par "uod...", alors le ’u’ sera associé avec ’a’ (première lettre), ’o’ sera associé avec
’b’, ’d’ sera associé avec ’c’, etc.
A partir de là, à vous de trouver ce qu’il faut faire pour inverser le mot de passe, mais
rappelez-vous que, d’après notre exemple, la lettre ’a’ devra être placée à la 21ème position
de notre mot de passe de décryptage. Un tri basé sur les premières lettres de chaque pair
permettrait naturellement d’ammener le ’a’ associé avec le ’u’ à la 21ème position...
2. Proposez deux méthodes de classe decode_string et decode_file réalisant le décodage
d’une chaîne de caractères et le décodage d’un fichier. Ces méthodes feront appel aux méthodes
correspondantes de la classe Encodeur.

4

Casser le mot de passe d’un texte

4.1

Description générale de la méthode (5mn)

Nous nous retrouvons maintenant dans la situation où un texte est crypté avec un mot de passe, mais
on ne connait pas ce dernier... On considère que le texte crypté était en anglais (ainsi, pas de problème
avec les accents).
On souhaite faire un programme qui testera des mots de passe "probables" afin que le texte décrypté
ressemble à de l’anglais.
Cependant, comment estimer si un texte ressemble à de l’anglais ? On possède un fichier quadgram_en.txt qui rassemble une très grande partie des combinaisons (389374 sur 456976) de quatre lettres
en anglais, avec un score de popularité à côté. Chaque quadgram est plus ou moins populaire selon la
langue utilisée (par exemple, en français, TION est un quadgram très utilisé car il apparait souvent).
Pour calculer à quel point une phrase est anglaise, on décomposera cette dernière en quadgram, puis
on calculera le score de chaque quadgram. Par exemple, pour calculer le score de "How are you ?", il
faudra aller chercher la valeur du quadgram "howa", celle du quadgram "owar", celle de "ware", de
"arey", de "reyo" et de "eyou", et additionner le log de toutes les valeurs récupérées.
Pour déchiffrer le texte, il faut trouver le bon mot de passe (qui est l’alphabet mélangé qui annulera
les effets du cryptage effectué)... Pour ce faire, commencez par générer le mot de passe "abcdefgh....xyz"
(c’est à dire que la lettre a est remplacée par a, b par b, etc... bref, rien ne change) et calculez le score
du texte complet (en mesurant le score de chaque quadgram).
Ensuite, permutez au hasard deux lettres de votre mot de passe, et refaîtes le calcul du score : si ce
dernier est meilleur que le précédent, conservez le nouveau mot de passe ; sinon, revenez au précédent.
Répétez ce processus jusqu’à ce qu’aucune permutation ne permette d’améliorer le score (par exemple, si
après 1000 permutations vous n’avez pas réussi à améliorer le score, considérez que vous pouvez arrêter
la boucle). Vous aurez alors normalement le bon mot de passe qui vous permettra de décrypter le texte.
Cette méthode s’appelle une descente de gradient, et nous allons maintenant voirf comment la coder
en Python.

Attaquer le code par permutation (35mn)
Questions
1. Proposez, dans votre classe, une méthode prenant en paramètre une chaîne de caractères et
renvoyant une nouvelle chaîne constituée uniquement les lettres de la première chaîne, avec
les majuscules transformées en minuscules, sans aucun signe de ponctuation ou autre. Une
seule ligne de code suffira à résoudre ce problème (considérez la chaîne de caractères comme
une liste, écrivez une compréhension de liste pour effectuer la tache, et regardez la fonction
join de la classe string).
2. Proposez, dans votre classe, une méthode prenant en paramètre un alphabet désordonné en
paramètre (un mot de passe pour le codage par substitution), et deux positions i et j dans
cet alphabet, dont la valeur par défaut sera None. Si i et j ont une valeur, on échange les
lettres à la position i et j et on renvoie le nouvel alphabet. Si i et j n’ont pas de valeur, on les
choisit au hasard puis on réalise l’échange. On renvoie le nouvel alphabet ainsi que la valeur
de i et j.
3. Proposez, dans votre classe, une méthode prenant en paramètre une chaîne de caractères et
renvoyant le score de cette chaîne basé sur le fichier quadgram avec lequel la classe avait été
construite. On considèrera, pour des soucis de performances, que la chaîne ne contient que
des lettres minuscules (aucun signe de ponctuation, aucun chiffre, les majuscules sont minuscules). On rappelle que le score d’une chaîne est la somme des log des scores des quadgrams
constituant cette chaîne.
Afin de réaliser cette tâche, commencez par construire une liste de chaque groupe de 4
lettres (quadgram) présent dans votre texte. Ensuite, à l’aide d’une compréhension de liste,
récupérez les scores associés à chaque groupe quadgram ainsi formé.
Pour vous aider dans votre travail, le score du texte mystery_text.txt transformé par
la fonction précédente (majuscule en minuscule et pas de ponctuation) est de 12176.13.
4. Proposez, dans votre classe, une méthode prenant une chaîne de caractères cryptée et qui
tentera de casser le code de cryptage. Votre méthode commencera par retirer, de la chaîne de
caractères, toutes les non lettres et transformera les majuscules en minuscules.
Ensuite, vous construirez un objet Encodeur initialisé avec un mot de passe égal à l’alphabet. Vous pourrez ensuite écrire la boucle principale :
(a) Calculer le score du texte décrypté par le mot de passe en cours (au début, le mot de passe
est égal à l’alphabet).
(b) Permuter deux lettres au hasard du mot de passe en cours, et décrypter le texte avec ce
nouveau mot de passe.
(c) Calculer le score du texte décrypté :
— Si ce texte a un meilleur score que le score calculé à la première étape, le nouveau mot
de passe devient le mot de passe en cours.
— Sinon, on annule la permutation pour revenir au mot de passe d’avant.
(d) Si on a tenté 1000 permutations de mots de passe d’affilée sans jamais améliorer le score,
on arrête et on affiche le texte décrypté. Sinon, on recommence à l’étape 2.
Evitez, dans votre implémentation, de créer un nouvel Encodeur à chaque tour de boucle,
mais essayez plutôt de modifier directement le mot de passe associé à l’encodeur.
Pensez, une fois le mot de passe trouvé, à effectuer un décryptage du fichier d’origine
avec ce mot de passe, afin de reconstituer le bon format de fichier (espaces, onctuations,

majuscules,...) dans le fichier de sortie.
Testez votre code sur le fichier mystery_text.txt.
